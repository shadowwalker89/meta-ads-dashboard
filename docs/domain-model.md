# Domain Model

This document defines the entities, relationships and ownership rules of the
Meta Ads Dashboard. It is the source of truth for the storage-agnostic domain
types in `packages/shared/src/domain/entities.ts` — the file and this document
must stay in sync. There are 10 entities.

All entities use string UUID ids generated by the storage implementation, never
by callers. Timestamps are ISO-8601 UTC strings at rest and `Date` objects in
the domain layer.

## Ownership & roles

```
super_admin ──► any client, any resource        (full access)
admin        ──► clients in AdminAssignment      (assigned clients only)
client       ──► own clientId only               (read-only)
```

The single authorization boundary that encodes these rules is
`apps/dashboard/lib/access.ts`. Nothing outside that module re-implements the
rule, and nothing storage-specific lives inside it.

## Entities

### 1. User
Application user account (not an auth provider identity).

| field      | type               | notes                                    |
|------------|--------------------|------------------------------------------|
| id         | string             |                                          |
| role       | `super_admin` \| `admin` \| `client` |              |
| fullName   | string             |                                          |
| email      | string             | UNIQUE (stable dev identity today)       |
| clientId   | string \| null     | set for `client` role; null otherwise    |
| createdAt  | Date               |                                          |

Relationship: a `client`-role User belongs to exactly one Client (or none).
Admins are linked to clients through AdminAssignment, not through clientId.

### 2. Client
A paying customer / report recipient.

| field            | type       | notes                                          |
|------------------|------------|------------------------------------------------|
| id               | string     |                                                |
| name             | string     |                                                |
| businessType     | string     |                                                |
| contactEmail     | string     |                                                |
| packageId        | string     | required — a Client is always assigned to one Package |
| packageAssignedAt| Date       | set at creation, refreshed on reassignment     |
| isActive         | boolean    | lifecycle flag; no delete exists               |
| createdAt        | Date       |                                                |

### 3. Package
An editable tier. Tiers are DB rows (seed data), never hard-coded logic.

| field             | type            | notes                                       |
|-------------------|-----------------|---------------------------------------------|
| id                | string          |                                             |
| name              | string          | display name (e.g. "Gold")                  |
| description       | string          |                                             |
| code              | string \| null  | stable machine key (e.g. "gold"); unique when present |
| collectionFrequency | number        | collections per day                         |
| maxAdAccounts     | number \| null  | null = unlimited                            |
| maxCampaigns      | number \| null  | null = unlimited                            |
| retentionDays     | number \| null  | report-history retention; null = indefinite |
| defaultVisibleKpis| DashboardKpiKey[] | fallback when a client has no preference    |
| features          | PackageFeatures | `charts`, `dataExport`, `advancedReporting` |
| pricingDefaults   | PackagePricingDefaults | starting point, not runtime truth      |
| metricThresholds  | Record           | reserved                                    |
| createdAt         | Date             |                                             |

Limits are enforced at the business layer by
`packages/database/src/services/package-enforcement.ts` using the shared
`isAtResourceLimit` helper — never by the UI and never by reading a tier code.

### 4. AdminAssignment
Links an admin User to the Clients they manage.

| field        | type   | notes                          |
|--------------|--------|--------------------------------|
| id           | string |                                |
| adminUserId  | string | FK User                        |
| clientId     | string | FK Client                      |
| assignedAt   | Date   |                                |

UNIQUE (adminUserId, clientId).

### 6. Campaign
A Meta campaign discovered by the Collector (or created for testing).

| field           | type             | notes                                   |
|-----------------|------------------|-----------------------------------------|
| id              | string           |                                         |
| adAccountId     | string           | FK AdAccount                            |
| name            | string           |                                         |
| objective       | string           |                                         |
| status          | string           |                                         |
| scrapedLabel    | string \| null   | label used by Collector find-or-create  |
| metaCampaignId  | string \| null   | Meta campaign id                        |

### 7. InsightSnapshot
A point-in-time metric reading for a Campaign. Snapshots are **cumulative**:
each row is the value at `capturedAt`, never a delta. The dashboard never
infers daily or period trends that a reading's own reporting window does not
explicitly carry.

| field            | type       | notes                                        |
|------------------|------------|----------------------------------------------|
| id               | string     |                                              |
| campaignId       | string     | FK Campaign                                  |
| capturedAt       | Date       | when the reading was collected               |
| impressions      | number     |                                              |
| clicks           | number     | maps to Meta "Link clicks"                   |
| linkClicks       | number     | maps to Meta "Link clicks" (same column)     |
| spend            | number     |                                              |
| ctr, cpc, cpm    | number     | derived ratios as reported by Meta           |
| reach            | number     |                                              |
| frequency, clicksAll, uniqueClicks, uniqueCtr | number | extended metric set (DEFAULT 0) |
| landingPageViews, outboundClicks, outboundCtr, leads, messagesStarted, messagesContacts, results, costPerResult, postReactions, postComments | number | extended metric set (DEFAULT 0) |
| rawPayload       | Record \| null | original raw values, for debugging only   |

### 8. DashboardPreference
Per-client (or per-user) dashboard configuration.

| field         | type             | notes                                   |
|---------------|------------------|-----------------------------------------|
| id            | string           |                                         |
| userId        | string \| null   | null for a client-level preference      |
| clientId      | string \| null   | null for a user-level preference        |
| visibleMetrics| DashboardKpiKey[]| the KPI set to show                      |
| theme         | `light` \| `dark` \| `system` |                          |
| updatedAt     | Date             |                                         |

KPI precedence: client DashboardPreference → Package.defaultVisibleKpis →
global default (`lib/package-settings.ts`).

### 9. AuditLog
Append-only record of financially/security-relevant admin actions. There is no
update or delete path.

| field            | type     | notes                                   |
|------------------|----------|-----------------------------------------|
| id               | string   |                                         |
| actorUserId      | string   | acting User                             |
| action           | string   | stable action key (e.g. `package.assigned`) |
| targetEntityType | string   | `client` \| `package` \| `ad_account`    |
| targetEntityId   | string   | id of the target entity                 |
| metadata         | Record \| null | minimal structured context, never secrets |
| createdAt        | Date     |                                         |

### 10. CollectorJob
One collection run for one AdAccount.

| field        | type                      | notes                        |
|--------------|---------------------------|------------------------------|
| id           | string                    |                              |
| adAccountId  | string                    | FK AdAccount                 |
| source       | `playwright` \| `meta_api`|                              |
| status       | `running` \| `success` \| `failed` |                  |
| startedAt    | Date                      |                              |
| finishedAt   | Date \| null              |                              |
| errorMessage | string \| null            |                              |

## Key relationships

```
User ──(client role)──► Client ──► Package
User ──(admin)──► AdminAssignment ──► Client
Client ──► AdAccount ──► Campaign ──► InsightSnapshot (append-only)
Client ──► DashboardPreference
AdAccount ──► CollectorJob
```

## Invariants

- A Client always references an existing Package.
- `metaAdAccountId` is optional and admin-set; the Collector refuses to run for
  an AdAccount without it (visible failure, never a silent empty run).
- Snapshots are append-only and cumulative — never recomputed or backfilled
  from deltas.
- Audit entries are created only AFTER a successful operation.
- No client or package deletion: deactivation (`is_active = 0`) and future
  lifecycle models are the only off-ramps.
